Executive Summary A Critical alert for suspected Qakbot activity fired on host Robert on 14 July 2023 at 05:32:35 UTC. The trigger was a phishing email, delivered the day before, carrying a 7z archive presented as a presentation. The archive held a macro-enabled Excel workbook, a malicious shortcut (readme.lnk) and a hidden batch script (ad.bat). Shortly after the workbook ran, EXCEL.EXE requested the same .dat file from three different external IP addresses over plain HTTP, while the shortcut launched cmd.exe to run ad.bat — a script that enumerates the user, network, domain and shares, force-terminates two Windows processes and attempts to repair the WebCache database. The behaviour is consistent with Qakbot and an attempt to run malicious code and prepare further compromise. The alert was assessed as a true positive.

Scenario

A Critical alert, classified as Data Leakage, fired on workstation Robert (172.16.17.189) on 14 July 2023 at 05:32:35 UTC (08:32:35 +03:00). The first-line analyst had found an email with a suspicious attachment and a ZIP → LNK → BAT execution chain that strongly suggested Qakbot, and escalated the case.

This investigation picks up the escalation: confirm whether the alert is a true positive, trace it back to the delivery email, analyse the attached files, and establish what actually ran on the host.

Key Findings

  • A phishing email carrying a 7z archive presented as a presentation passed the email gateway (action: Allowed).
  • The archive held a macro-enabled workbook, a malicious shortcut (readme.lnk) and a hidden batch script (ad.bat).
  • The workbook macro runs automatically on open, hides worksheet content, builds its formulas dynamically, executes indirectly through Application.Run and references several external payload-like files, including a regsvr32 -silent ..\Drezd.red command.
  • After normal Office traffic, EXCEL.EXE (PID 4364) requested the same .dat file from three unrelated external IPs over unencrypted HTTP, a pattern consistent with a macro using fallback servers.
  • readme.lnk launches cmd.exe, which runs ad.bat to enumerate the user, network, domain, shares and local groups, force-terminate taskhostw.exe and dllhost.exe, and attempt recovery of the WebCache database.
  • The alert was assessed as a true positive consistent with Qakbot activity; escalation to incident response is warranted.
  • Not confirmed: the logs show the three payload requests being permitted, but not whether any payload was actually delivered.
  • Not confirmed: the WebCache folder and WebCacheV01.dat targeted by ad.bat were not present in AppData\Local\Microsoft\Windows on the evidence left on the endpoint, so recovery of browser data by the script is not confirmed.

Recommended Actions

These are recommendations from the investigation, not findings.

  • Isolate Robert (172.16.17.189) and escalate to incident response.
  • Block 111.90.151.238, 190.14.37.241, 84.32.188.11 and 201.226.241.213, and the sender domain digitalzedi[.]com.
  • Hunt across endpoints for readme.lnk, ad.bat, the file hashes and requests for 45121.3553172454.dat.
  • Search the mail system for other messages from the same sender or carrying form.7z, and remove them.
  • Reset credentials for the affected user and review other activity from the host.
  • Block or tightly restrict macro execution in files received from the internet.

Analyst Notes

Started from the alert and the L1 note, then pivoted to the delivery email to establish how the files reached the host.
Filtered log management on the host IP: normal Office traffic first, then plain-HTTP requests from EXCEL.EXE to three unrelated hosts, all permitted.
Requesting one payload name from three IPs right after the Microsoft connections is typical of a macro working through fallback servers.
Reconciled time zones before building the timeline: log-management times are UTC, Sysmon is three hours later, which matches the alert’s +03:00 offset.
Parsed readme.lnk to confirm it runs cmd.exe /c against ad.bat, and read the strings extracted from the workbook to confirm the macro indicators.
Checked AppData\Local\Microsoft\Windows, the path the script targets, for WebCache data and found none on the evidence left on the endpoint.
The evidence timestamps the workbook’s network activity and the alert, but does not separately timestamp the cmd.exe and ad.bat run, so the order of the two execution paths is not established.
