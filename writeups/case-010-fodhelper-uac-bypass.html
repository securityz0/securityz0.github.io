Executive Summary A High-severity malware alert fired on host Fiona after Missing_DLL.exe called fodhelper.exe. The cause was a phishing email presented as a Microsoft helpdesk message, urging the user to download a “DLL package” from a link. The link delivered a ZIP from an Amazon S3 bucket. Once its executable ran, it wrote a PowerShell command into the ms-settings registry key under HKCU and launched fodhelper.exe, an auto-elevating Microsoft binary, so the command ran with administrator rights and without a UAC prompt. The command created a local account, onebl00d, and added it to the Administrators group. The registry key and the account were both confirmed on the endpoint. The alert’s own timestamp does not line up with the other sources and was not used to order events.

Scenario

A High-severity alert, classified as Malware, fired on workstation Fiona (172.16.17.73) when Missing_DLL.exe, running from the user’s Downloads folder, called fodhelper.exe, a legitimate Windows process. The first-line analyst noted that only three antivirus engines flagged the file on VirusTotal and escalated it for detailed analysis.

The goal was to trace the file back to how it arrived, work out what it did on the host, and confirm the result on the endpoint itself.

Delivery and Download

The email presented itself as a Microsoft helpdesk message. It asked the recipient to download a ZIP through a link, extract it, and run “missing_dlls.exe” to resolve missing DLL issues. The gateway allowed it.

The log-management view shows the Exchange SMTP entry, followed by three OS events on the endpoint. The Sysmon detail behind them gives the download source and the file that was created.

Key Findings

  • A phishing email presented as a Microsoft helpdesk message urged the user to download a “DLL package” through a link, and the gateway allowed it.
  • The link led to Missing_DLL.zip on an Amazon S3 bucket. Chrome saved it with ZoneId=3 (internet), and Explorer extracted Missing_DLL.exe into the Downloads folder.
  • Missing_DLL.exe wrote a PowerShell command into the (Default) value of HKCU\Software\Classes\ms-settings\Shell\Open\command and launched fodhelper.exe, a UAC bypass that abuses an auto-elevating Microsoft binary.
  • The planted command, run elevated, created the local user onebl00d and added it to the Administrators group.
  • On the endpoint, the registry value is present and onebl00d exists as an active Administrators member with no expiry. At the time of the check, its last logon was Never.
  • Timestamps do not reconcile across sources: the alert’s time (11:37:00 +03:00) does not fit the log-management or Sysmon times, so event order comes from the logs, not the alert.

Malicious File Analysis

fodhelper.exe is a signed Microsoft binary that elevates automatically. When it runs, it reads HKCU\Software\Classes\ms-settings\Shell\Open\command. Settings under HKCU\Software\Classes belong to the current user and can override system-wide ones, so a standard user can plant a command there.

  1. Missing_DLL.exe writes a PowerShell command into the (Default) value of the ms-settings command key and sets a DelegateExecute value next to it.
  2. It launches fodhelper.exe with the runas verb.
  3. fodhelper.exe reads the key and runs the planted command instead of opening the Settings app.
  4. Because fodhelper.exe is a trusted, auto-elevating binary, the command runs with administrator rights without a UAC prompt.
  5. The elevated command runs net user to create onebl00d and net localgroup to add it to Administrators.

Endpoint Validation

Both effects of the sample were checked on the endpoint rather than inferred from the logs alone.

Analyst Notes

Started from the alert, where Missing_DLL.exe called fodhelper.exe, and worked backwards to how the file reached the host.
Matched the Exchange entry to the phishing email, then used the Sysmon file-stream event for the Zone.Identifier, which gave the download URL directly.
The Sysmon registry event showed the written value, which already contained the full PowerShell command and the account name.
Decompiled the sample to confirm the registry writes and the runas launch of fodhelper.exe, rather than relying on the registry event alone.
Checked the registry key and the local account directly on the endpoint, so the outcome did not rest on logs only.
The process tree in Figure 6 has different PIDs from the endpoint’s Sysmon events, so it was used for the shape of the process chain, not to tie events to specific PIDs.
